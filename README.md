# AI Shipping Ledger Mini Program

面向香皂发货业务的 AI 发货台账微信小程序。

核心目标不是“OCR 转文字”，而是：

1. 原始发货单永久保存、可追溯；
2. AI 多级识别与历史商品库复核；
3. 只有无法确定的字段才进入人工介入；
4. 发货数据结构化保存，支持按工厂 / 产品 / SKU / 日期统计；
5. 同一 SKU 在同一发货单中的多处记录保留原始明细，同时可自动汇总；
6. 任何统计结果都可以追溯到原图与字段位置；
7. 完整数据库和原始图片可以整体导出，不锁死在平台内。

## V1 范围

- 上传照片 / PDF
- 原图、增强图、缩略图三层文件记录
- OCR 初识别
- 多模态大模型二次复核
- 产品库 / SKU / 工厂历史检索
- 规则校验（箱数、装箱数、总件数）
- 字段级可信度与人工复核
- 发货单台账
- 同 SKU 自动汇总
- 原图定位追溯
- 修改审计日志
- Excel / CSV / JSON / 完整归档包导出

## Phase 2：已完成微信小程序交互骨架

当前仓库已经包含可导入微信开发者工具的 `miniprogram/`：

- 首页：累计发货单 / 箱数 / 件数、最近记录
- 上传：拍照、相册、聊天文件、PDF，多图视为同一张发货单
- 原图：识别前优先使用 `wx.saveFile` 持久化本地原件
- 识别：当前明确使用 Mock AI，下一阶段替换为真实识别服务
- 详情：商品名称、SKU、规格、箱数、装箱数可以直接修改
- 自动保存：字段失焦即保存并写审计日志
- 自动算账：`总件数 = 箱数 × 每箱件数`
- 人工介入：演示了字段级“待复核”状态
- 台账：结构化记录自动进入历史台账
- 原图追溯：详情页可直接预览上传的原始图片

详见：`docs/03-miniapp-prototype.md`

## 在微信开发者工具中运行

1. 克隆本仓库。
2. 微信开发者工具 → 导入项目。
3. 选择仓库根目录；`project.config.json` 已声明 `miniprogramRoot`。
4. 当前 `appid` 为 `touristappid`，正式接云开发前替换成自己的小程序 AppID。
5. 打开后即可测试：上传 → 演示识别 → 修改 → 台账 → 原图查看。

## 当前限制

Phase 2 仍是本地可运行原型：

- 数据存储在小程序本地 Storage；
- 原图优先保存到小程序本地文件；
- OCR / 多模态大模型尚未接入；
- CloudBase / 正式数据库尚未接入；
- 完整数据库导出尚未实现。

这些限制会在后续阶段按数据安全和可迁移原则逐步替换，不改变已经确定的领域模型。
